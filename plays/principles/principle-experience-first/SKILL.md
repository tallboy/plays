# Experience First

**The play:** Don't ship half-baked. Ship one thing that's excellent, not ten things that are rough.

## When to Apply This

- ✅ Prioritizing features
- ✅ Deciding when to ship
- ✅ Cutting scope
- ✅ Any time pressure exists

## The Rule

**One polished feature > five rough features.**

Not:
- ✗ "I'll ship all these and polish later"
- ✗ "It's good enough"
- ✗ Shipping incomplete work to hit a deadline

Instead:
- ✓ Pick the most valuable feature
- ✓ Polish it until it shines
- ✓ Ship that one thing
- ✓ Users love it, come back for more

## How

### 1. Prioritize
Which one feature would delight users most?

### 2. Build It Well
No corners cut.

### 3. Polish
Testing, edge cases, documentation, UX.

### 4. Ship It
Done > perfect.

### 5. Iterate
Next feature, same care.

## Examples

**Bad:** Ship 5 incomplete features.
**Good:** Ship 1 complete feature. Users love it.

## The Principle in One Sentence

**Delight beats feature count. Always.**
